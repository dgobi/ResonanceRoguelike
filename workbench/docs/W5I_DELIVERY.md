edit-only profile. The owner deliberately selects saved room candidates, weights,

## Contract, lifecycle and preservation

`authored-submap-selection-1` owns fixed identity `authored_submap_selection`,
integer version 1, at `data/generation/authored_submap_selection.json`. It supports
one existing type (`barrow`, `cave`, `vault`), chance in [0,1], and unique saved
ordinary room candidates with positive finite relative weights. Unsupported
versions/types, malformed fields, duplicate IDs and bad numbers have field-level
diagnostics. Missing/ineligible references are warnings while disabled/zero chance,
errors for active nonzero policy. Corrupt explicit files are never treated as absent.

Shared game modules supply source eligibility, compiler/reference checks,
factory checks and readable payload semantics. The protected laboratory, template,
nested/ambiguous/missing and unsupported original sources cannot be promoted by
candidate JSON or renderer flags. Historical loadable unsupported content and
warnings remain intact. The existing loader's structure-catalogue strictness is
unchanged; this adds no unrelated cleanup gate.

The selector uses a distinct SHA-256-derived random domain and sorted candidate
identities. Occurrence, type, seed, name, SubMap identity/depth, geography, plans,
population and entrance streams retain their prior behavior. Three complete small
legacy-world golden hashes come from the unmodified start generator. Actual
production tests compare absent/disabled/zero policies and enabled assignment,
including full ordinary shared-plan world state and lazy construction.

Policy resolution occurs inside new-world generation before atomic publication,
never in `DataLoader` initialization or restored-world enrollment. Recorded IDs
are persisted by the existing save path. No world-plan/save/generation revision
was bumped or historical world relabelled. Authored scenes use the established
construction/population path without procedural loot or ambient actors layered on.

Workbench uses the existing token, exact-source history, dirty/conflict state,
accepted draft, recovery and single-file transaction. The host admits only this
exact generation file; descriptors/recovery cannot invent another target. Existing
dependency stamps, original-source policy, review consumption, cancellation,
pinning, rollback and expected-hash reopen remain active. **Add this room** only
stages a row. Save dependencies first: parked drafts do not overlay the profile.
