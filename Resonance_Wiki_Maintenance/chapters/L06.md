# L06 — Build a playable place

Build a room whose layout supports a small decision: read a clue, approach or avoid a watcher, prepare a useful meal and keep an exit reachable. You can author places before learning to author every item or creature; all dependencies are supplied.

## Independent starting fixture

Use `guide1_encounter.json`, the ready watcher, note/carrier, ration, raw ingredient, fire and vessel. Run:

```powershell
& $ResonancePython -X utf8 -B Resonance_Wiki_Maintenance/practice.py L06 --output evidence/guide-1/l06
& $ResonancePython -X utf8 -B Resonance_Wiki_Maintenance/practice.py L06 --play
```

Predict what persists when you leave and return, what Reset capture means, and whether a successful Test room makes the place appear naturally. The automated solution acquires/reads the clue, advances the actual guard, uses stairs both ways, checks that the acquired note does not respawn, and cold-loads the owned scene. It is a controlled authored-room test.

## Purpose-labeled construction

**Make geometry traversable.** Layers must be rectangular and match width/height. Legend symbols name actual terrain. Keep the explicit player start and stairs on reachable walkable tiles. A pleasing picture with an inaccessible return is not a playable room.

**Give each element a job.** Put the clue near arrival; give the threat a readable position; give contents a use; place the fire where the player can approach without blocking the return. A room can imply a route without forcing one. Access screens/coffers can add careful work, force or dose choices through the bounded access profile system; arbitrary lock flags cannot.

**Construct real things.** Direct `item`, `creature`, admitted `decor`, container, remains and screen records use different consumers. Do not substitute historical `body`/`stele` declarations or unsupported nested weighted actors. Save dependencies before the room.

## Vary, diagnose, make

**Guided variation:** move the clue and ingredient to make the safe route longer while leaving the return clear. Copy the full room to `authoring/guide1/room.json`, keep `guide1_encounter`, and run `L06 --draft`. The fixed journey assumes the note is at arrival; a moved clue requires adapting its route or using manual ordinary input. Do not call a failed fixed-route assertion proof that valid geometry is broken.

**Fault:** place a blocking decorative object on the only route to the stairs. A JSON parser will pass. Use access preview/reachability and the actual return journey to distinguish geometry from missing stair identity. Restore a route, not a teleport in the test.

**Independent task:** make a different compact encounter with two approaches, one useful discovery, one risk, a practical reward and an exit. Use the supplied assets or your own fiction. Decide whether the clue is reliable, and ensure the game actually supports its claim. Acceptance: constructor/refs valid, ordinary acquisition/use, threat responds, return works, depleted contents remain depleted, and a fresh process preserves the scene.

## Lifetimes and restart

The running capture is immutable input, not live source. A new capture sees saved changes. New instances are factory-built; loaded actors/items retain captured state. An assigned unbuilt room can use a same-ID edit; a generated room retains its owned scene. A new world still needs [L07 enrollment](#L07). Restart the fixed fixture without touching personal saves. Revisit by adding one access method and explaining its commitment/cancellation rules from the actual source.
