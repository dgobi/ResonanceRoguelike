## Define requirements and output

Workbench's Recipe editor starts from an eligible passive preparation. Save the output item first, then create a recipe variant. Use Requirements/Preparation/Output/Test requirements; the test probe is an allocation aid, not completed world work. The full equivalent recipe is:

`components` selects physical material; `requires_ambient` supplies a condition. A `tools` row would allocate a different physical object and retain it. A conjunction requires one object carrying all its tags. Quantity means distinct allocated objects, not one object pretending to satisfy every slot. `consumed_on_use:false` excludes automatic material selection but does not make a material reusable if you affirmatively choose it.

`CraftScreen._attempt_craft` asks `crafting.plan_craft` for a plan. Passive work opens placement without consuming yet. Confirmation revalidates the selected objects, heat and location, consumes the selected ingredients and creates map-owned work in `LocalMap.processing_layer` with an output ID and remaining time. `_tick_processing_map` advances that job during paid phases. Vessel jobs additionally retain the exact physical vessel. Rendering does not cook food.

## Vary, diagnose and make

**Guided variation:** copy the recipe to `authoring/guide1/meal.json`, change `processing_turns` to 5 and run it with `--draft`. The expected remaining value after confirmation becomes 4. The driver reads your candidate's duration, checks that placement paid the first phase, and waits exactly the remaining four. This is a changed requirement, not a cosmetic renaming. The complete variation is the same file with that value changed; expected completion is the fifth paid phase including placement.

**Fault:** only a torch is available. Look at the actual ambient list and the explicit stationary-fire requirement. Adding a material with a burning tag does not turn it into an environmental fire. Another fault is selecting a protected object automatically; use the supported material chooser or choose an eligible ingredient, not a silent flag override.

**Independent task:** design a preparation with two distinct inputs and a retained tool, or a longer passive batch with a different usable output. Decide the ownership/time contract before editing. Acceptance: output dependency saved, missing requirement rejects unchanged, cancel is free, the intended physical inputs are spent once, tool remains, and result is useful through ordinary input.

## Lifetime and restart

Running definitions stay loaded. New work reads the current recipe; existing committed jobs capture their parameters and output ID. A generated scene owns work even while not active, according to its scene/time rules; it is not a fresh recipe each frame. Save/load must retain remaining work and ingredients/vessel ownership.
