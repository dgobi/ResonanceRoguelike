## Complete integration

`PerkScreen._commit` debits points, adds the ID and calls `_register_player_perks`. The latter cleans derived bonuses, removes functions tagged `_is_perk_handler`, installs active hook definitions from `HANDLER_MAP`, and restores current bonuses. `HookRegistry.register` itself merely appends; idempotence belongs to the registration route and correct tagging.

The complete `cadence_turn` handler in [the solution reference](#practice-solutions) validates the inner state, creates `{version:1, paid:0}` on absence, increments once and returns `add_message` every third phase. `_advance_turn` fires `ON_TURN` **before** incrementing world time. Hook effect merging turns messages into a list; engine `_apply_effects` actually consumes that list. This is a live result path, unlike the generic status stubs.

State lives in `player.perks.perk_state['guide1_cadence']`. Removal detaches the callback but deliberately retains history; reacquisition can resume it. Existing serialization carries the dictionary, while the delivered validator checks the new inner schema before save/load replacement. Fresh processes install the same patch before construction/loading. The solution binds both `save_components.validate_components` and the alias imported by `save_manager`; missing the alias would leave a load path unchecked.

## Compare with venom, a working timed condition

The production chain is `venom.deliver` after qualifying damaging nonlethal contact → captured state on the **victim's fighter** → `effect_lifecycle.finish_turn` → `venom.age` → warning/full paralysis/recovery/removal. `aged_phase` prevents one owner aging twice in one paid boundary. Save validation retains complete dose/source provenance; absent state restores absent.

Full physical paralysis affects physical actions and active defense. It is not a movement penalty you can preserve by checking only movement keys. Treatment, dead-owner cleanup and scene ownership matter. Generic `add_status`/`remove_status` in engine `_apply_effects` contain unimplemented branches; they are not a way to install this lifecycle. To create a new condition, explicitly implement delivery, owner/schema/defaults, phase aging, every affected action/defense gate, feedback, treatment/removal and cold continuation. This lesson's new callback is intentionally simpler and does not pretend to do those jobs.

## Vary, diagnose, make

**Guided variation:** report every second paid phase. Change the modulo condition from 3 to 2 in the copied solution, regenerate the fixed patch contract deliberately, then update expected message/count evidence. Keep the saved counter schema unchanged; its meaning is still total paid phases.

**Fault:** omit `_is_perk_handler`. Re-register twice, then a single wait can increment multiple times because old callbacks remain. Another fault is declaring `ON_STATUS_APPLIED` without finding a real dispatch for the intended case. Search the actual `hooks.fire` calls and result consumer.

**Independent task:** make a new event response that communicates a useful observed fact, with a real existing event and no hidden-information shortcut. Choose whether removal preserves or resets its state. Acceptance: normal acquisition, exactly one callback after repeated rebuilds, live event/effect consumption, cleanup, strict saved schema and a cold process that continues behavior.
