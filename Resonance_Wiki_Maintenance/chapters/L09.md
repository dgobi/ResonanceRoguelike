# L09 — Add a weapon technique

Give a practice weapon a Q technique that uses an existing armour/dodge-bypass result with its own cooldown identity. This is a new data combination; [L10](#L10) makes a genuinely new primitive in Python.

## Starting state and prediction

The encounter, target and complete Practice Blade are supplied independently. The automated check explicitly stages the target adjacent to the player, leaving hit resolution and paid-time rules intact. Predict whether two actions with the same ID share cooldown, whether a large `range` creates free targeting, and whether a cooldown rejection spends a phase.

The important identity is `guide1_opening`, not merely the weapon's ID. `get_moveset_action` selects Q/R data; `execute_moveset` parses a `MovesetResult`; `_try_moveset_action` selects a legal target, resolves combat and applies supported result fields; `_handle_key_local` commits `_weapon_action_phases`. The result carries a request; the consumer decides its actual effect.

## What the implementation actually supports

Targets are the nearest living blocking fighter passing `melee_attack_legal`. A larger range does not remove melee legality or create an arbitrary ranged cursor. Action-ID cooldown is shared wherever that ID is reused. HP/position gates can reject freely, but their discarded result messages are not reliably displayed; observe state rather than promising that feedback.

`pool_turns` and `on_kill_only` are parsed fields without the broad engine lifecycle their names imply. `place_pool` places decor on a kill; it does not establish timed deletion. Generic perk `add_status` is also not a working universal status API. Select fields with a live consumer and describe precisely what your scenario exercised.

## Vary, diagnose, make

**Guided variation:** add an R entry with a distinct ID, longer cooldown and supported `suppress_ability_turns`. Keep a modest damage multiplier. The complete variation is a second moveset object with `id: guide1_interrupt`, `key: R`, `turn_cost: 1`, `cooldown: 6`, `range: 1`, `damage_mult: 1`, and `effects: {suppress_ability_turns: 2}`; give it a name/callout. This does not prove the selected target has a suppressible ability—choose a real consumer before claiming that outcome.

**Fault:** copy the Q entry to another weapon but retain `guide1_opening`. Observe the shared cooldown, then fix by giving the intended independent technique a unique action ID. Renaming only the display name does not repair it.

**Independent task:** choose a technique with a meaningful tactical cost or condition. Decide whether it should reliably connect, require an opening, or provide information. Acceptance: independent identity, supported consumed fields, reachable input, accepted/rejected and missed-contact timing as relevant, and observable feedback. A strong description is not evidence that a declared field works.

## Lifetime and restart

Running weapon definitions are cached; new sessions read new movesets. Saved physical equipment and engine cooldown state have explicit restore behavior, while combat definition lookup can use current session data. Existing scenes do not respawn the weapon. New worlds still need appearance references. Rerun the fixture to reset; keep only your intended source diff.
